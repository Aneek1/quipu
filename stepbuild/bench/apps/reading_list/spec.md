A reading list where each book has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `title` (a string that is not empty after trimming whitespace), a required `author` (a string that is not empty after trimming whitespace) and a `status` (one of the strings `"to-read"`, `"reading"` or `"done"`, which defaults to `"to-read"` when it is left out); every new app instance starts with no items. The API has five JSON endpoints: `GET /api/books` returns all books as a JSON array; `POST /api/books` creates a book from a JSON body with `title`, `author` and optional `status` and returns the new book with its `id` and status 201; `GET /api/books/<id>` returns one book; `PUT /api/books/<id>` updates a book and returns the updated book with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `title` is 400); `DELETE /api/books/<id>` deletes a book and returns 200 or 204. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: `title` missing, not a string, or empty after trimming whitespace; `author` missing, not a string, or empty after trimming whitespace; `status` sent but not exactly one of `"to-read"`, `"reading"` or `"done"`. A field sent as `null` counts as sent, so `null` for a field is 400. Any request for an `id` that does not exist returns 404. The page shows the list of books (title, author and status) with a delete button on each and a form to add a new book.
