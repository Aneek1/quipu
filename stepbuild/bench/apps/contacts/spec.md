A contacts book where each contact has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `name` (a string that is not empty after trimming whitespace), a required `email` (a string that contains exactly one `@` with at least one character before it and at least one after it) and a `phone` (a string that defaults to an empty string when it is left out); every new app instance starts with no items. The API has five JSON endpoints: `GET /api/contacts` returns all contacts as a JSON array; `POST /api/contacts` creates a contact from a JSON body with `name`, `email` and optional `phone` and returns the new contact with its `id` and status 201; `GET /api/contacts/<id>` returns one contact; `PUT /api/contacts/<id>` updates a contact and returns the updated contact with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `name` is 400); `DELETE /api/contacts/<id>` deletes a contact and returns 200 or 204. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: `name` missing, not a string, or empty after trimming whitespace; `email` missing, not a string, or not exactly one `@` with at least one character on each side of it; `phone` sent but not a string. A field sent as `null` counts as sent, so `null` for a field is 400. Any request for an `id` that does not exist returns 404. The page shows the list of contacts (name, email and phone) with a delete button on each and a form to add a new contact.
