A bookmarks app where each bookmark has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `title` (a string that is not empty after trimming whitespace), a required `url` (a string that starts with `http://` or `https://`) and a `note` (a string that defaults to an empty string when it is left out); every new app instance starts with no items. The API has five JSON endpoints: `GET /api/bookmarks` returns all bookmarks as a JSON array; `POST /api/bookmarks` creates a bookmark from a JSON body with `title`, `url` and optional `note` and returns the new bookmark with its `id` and status 201; `GET /api/bookmarks/<id>` returns one bookmark; `PUT /api/bookmarks/<id>` updates a bookmark and returns the updated bookmark with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `title` is 400); `DELETE /api/bookmarks/<id>` deletes a bookmark and returns 200 or 204. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: `title` missing, not a string, or empty after trimming whitespace; `url` missing, not a string, or not starting with `http://` or `https://`; `note` sent but not a string. A field sent as `null` counts as sent, so `null` for a field is 400. Any request for an `id` that does not exist returns 404. The page shows the list of bookmarks (title as a link to the url, and the note) with a delete button on each and a form to add a new bookmark.
