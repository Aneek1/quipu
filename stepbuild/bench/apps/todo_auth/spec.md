A todo list with user accounts, where people register, log in with a Flask session cookie and see only their own todos. Users are kept in memory (in the app instance, never in a file) with a `username` and a `password`; every new app instance starts with no items and no users. The account endpoints are: `POST /api/auth/register` creates a user from a JSON body with `username` (a string that is not empty after trimming whitespace) and `password` (a non-empty string) and returns `{"username": ...}` with status 201, or status 409 with an `error` key when that username is already taken; registering does not log the user in; `POST /api/auth/login` checks a JSON body with `username` and `password`, stores the user in the session and returns `{"username": ...}` with status 200, or status 401 with an `error` key when they do not match a registered user (including an unknown username or a missing field); `POST /api/auth/logout` clears the session and returns status 200 (also when nobody is logged in). Each todo belongs to the user who created it and has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `title` (a string that is not empty after trimming whitespace) and a `done` flag (a boolean that defaults to false when it is left out). The todo endpoints are: `GET /api/todos` returns the logged-in user's todos as a JSON array; `POST /api/todos` creates a todo from a JSON body with `title` and optional `done` and returns the new todo with its `id` and status 201; `GET /api/todos/<id>` returns one todo; `PUT /api/todos/<id>` updates a todo and returns the updated todo with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `title` is 400); `DELETE /api/todos/<id>` deletes a todo and returns 200 or 204. Every todo endpoint returns status 401 with an `error` key when nobody is logged in. A user can never see or change another user's todos: a todo `id` that belongs to someone else is treated as missing and returns 404, exactly like an `id` that does not exist. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: on register, `username` missing, not a string, or empty after trimming whitespace, and `password` missing, not a string, or empty; on todos, `title` missing, not a string, or empty after trimming whitespace, and `done` sent but not a boolean. A field sent as `null` counts as sent, so `null` for a field is 400. Any request for a todo `id` that does not exist returns 404. The page shows a login form (with a register button) when logged out, and when logged in the list of the user's todos with a delete button on each, a form to add a new todo and a logout button.
