An expenses tracker where each expense has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `description` (a string that is not empty after trimming whitespace), a required `amount` (a positive number: a JSON integer or decimal greater than zero; zero, negative amounts, strings and booleans are rejected) and a `category` (a string that defaults to `"general"` when it is left out); every new app instance starts with no items. The API has five JSON endpoints: `GET /api/expenses` returns all expenses as a JSON array; `POST /api/expenses` creates an expense from a JSON body with `description`, `amount` and optional `category` and returns the new expense with its `id` and status 201; `GET /api/expenses/<id>` returns one expense; `PUT /api/expenses/<id>` updates an expense and returns the updated expense with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `description` is 400); `DELETE /api/expenses/<id>` deletes an expense and returns 200 or 204. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: `description` missing, not a string, or empty after trimming whitespace; `amount` missing, not a number (a string or a boolean is not a number), or not greater than zero (so a negative amount or 0 is 400); `category` sent but not a string. A field sent as `null` counts as sent, so `null` for a field is 400. Any request for an `id` that does not exist returns 404. The page shows the list of expenses (description, amount and category) with a delete button on each and a form to add a new expense.
