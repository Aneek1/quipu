A notes app where each note has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `title` (a string that is not empty after trimming whitespace) and a `body` (a string that defaults to an empty string when it is left out); every new app instance starts with no items. The API has five JSON endpoints: `GET /api/notes` returns all notes as a JSON array; `POST /api/notes` creates a note from a JSON body with `title` and optional `body` and returns the new note with its `id` and status 201; `GET /api/notes/<id>` returns one note; `PUT /api/notes/<id>` updates a note and returns the updated note with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `title` is 400); `DELETE /api/notes/<id>` deletes a note and returns 200 or 204. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: `title` missing, not a string, or empty after trimming whitespace; `body` sent but not a string. A field sent as `null` counts as sent, so `null` for a field is 400. Any request for an `id` that does not exist returns 404. The page shows the list of notes (title and body) with a delete button on each and a form to add a new note.
