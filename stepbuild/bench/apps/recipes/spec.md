A recipes app where each recipe has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `title` (a string that is not empty after trimming whitespace), `ingredients` (a list of strings, each not empty after trimming whitespace, that defaults to an empty list when it is left out) and `minutes` (the cooking time, an integer that is 0 or more, not a boolean, that defaults to 0 when it is left out); every new app instance starts with no items. The API has five JSON endpoints: `GET /api/recipes` returns all recipes as a JSON array; `POST /api/recipes` creates a recipe from a JSON body with `title` and optional `ingredients` and `minutes` and returns the new recipe with its `id` and status 201; `GET /api/recipes/<id>` returns one recipe; `PUT /api/recipes/<id>` updates a recipe and returns the updated recipe with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `title` is 400); `DELETE /api/recipes/<id>` deletes a recipe and returns 200 or 204. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: `title` missing, not a string, or empty after trimming whitespace; `ingredients` sent but not a list, or holding an entry that is not a string or is empty after trimming whitespace; `minutes` sent but not an integer (booleans and decimals are rejected) or negative. Any request for an `id` that does not exist returns 404. The page shows the list of recipes (title, minutes and ingredients) with a delete button on each and a form to add a new recipe, where the ingredients are typed as one comma-separated line.
