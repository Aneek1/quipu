A todo list where each todo has an integer `id` assigned by the server (ids are never reused, even after a delete), a required `title` (a string that is not empty after trimming whitespace) and a `done` flag (a boolean that defaults to false when it is left out); every new app instance starts with no items. The API has five JSON endpoints: `GET /api/todos` returns all todos as a JSON array; `POST /api/todos` creates a todo from a JSON body with `title` and optional `done` and returns the new todo with its `id` and status 201; `GET /api/todos/<id>` returns one todo; `PUT /api/todos/<id>` updates a todo and returns the updated todo with status 200, where PUT accepts any subset of the fields; fields left out keep their values; a field that is sent follows the same rules as on create (so an empty `title` is 400); `DELETE /api/todos/<id>` deletes a todo and returns 200 or 204. The validation rules, each rejected with status 400 and a JSON body with an `error` key, are: `title` missing, not a string, or empty after trimming whitespace; `done` sent but not a boolean. A field sent as `null` counts as sent, so `null` for a field is 400. Any request for an `id` that does not exist returns 404. The page shows the list of todos with a delete button on each and a form to add a new todo.
