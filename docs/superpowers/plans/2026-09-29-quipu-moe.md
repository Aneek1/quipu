# quipu-moe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, test and smoke-run everything needed to pretrain quipu-moe (~0.98B total / ~135M active, K3-core MoE, new 32k tokenizer, 60/40 code/text) on a rented RTX 5090 under a $20 cap, so the paid session only downloads data, runs A/B tests and trains.

**Architecture:** Extend the existing `quipu` package rather than fork it. New focused modules: `quipu/bpe.py` (tokenizer backend), `quipu/moe.py` (experts, router, Quantile Balancing), `quipu/attnres.py` (Block Attention Residuals), `quipu/model_moe.py` (the MoE model), `quipu/optim/muon.py` (per-head Muon). The trainer, shard builder, evaluation and export learn a `model.kind = "dense" | "moe"` switch and a tokenizer-from-config switch, keeping quipu-114m working unchanged. Box orchestration lives in `scripts/remote/`.

**Tech Stack:** Python 3.13 (uv), PyTorch 2.11 cu128, Hugging Face `tokenizers`, pyarrow/datasets for data, pytest. Linux RTX 5090 for the paid run; Windows laptop RTX 5060 (8 GB) for development and smoke tests.

**Spec:** `docs/superpowers/specs/2026-09-29-quipu-moe-design.md` — read it first, **including §11 (multilingual amendment), which supersedes earlier numbers.** Owner decisions: K3-core scope (A), ~10B tokens target trimmed by a **$20 cap** (~9B), 60% code / 40% text.

### Task M1: BPE tokenizer backend, trainer and gate

**Files:** Create `quipu/bpe.py`, `scripts/train_tokenizer.py`, `scripts/tokenizer_gate.py`, `tests/test_bpe.py`. Modify `quipu/tokenizer.py`. Add dependency `tokenizers`.

Interfaces:
```python
class BPETokenizer:
    def __init__(self, path: str | Path) -> None            # loads tokenizer.json
    @property vocab_size -> int; @property eot -> int
    def encode(self, text: str) -> list[int]                # ordinary text; special-token strings are NOT parsed from text
    def encode_with_special(self, text: str) -> list[int]   # parses <|user|> etc. (for chat later)
    def decode(self, ids: list[int]) -> str
    def special_id(self, name: str) -> int
SPECIAL_TOKENS = ("<|endoftext|>", "<|system|>", "<|user|>", "<|assistant|>", "<|end|>", "=== FILE: ", "=== END FILE ===")
def make_tokenizer(tokenizer: str) -> Tokenizer | BPETokenizer   # "gpt2" or a path to tokenizer.json
```
`train_tokenizer.py --out artifacts/tokenizer/tokenizer.json --sample-bytes 1_000_000_000 --vocab 32768`: streams FineWeb-Edu and github-code-clean (permissive, spec §5 language weights) until the byte budget at 60/40, trains byte-level BPE with the spec §4.1 pre-tokeniser (space runs up to 16 as own pieces, tabs likewise, newlines separate, digits individual, GPT-4-style word regex), reserves SPECIAL_TOKENS at fixed low ids, writes tokenizer.json + a sample manifest (sources, bytes per source, sha256). Default sample 1 GB (laptop RAM); `--sample-bytes 2e9` on the box.

`tokenizer_gate.py --tokenizer PATH --text-sample N --code-sample N`: measures on held-out text and code (fresh docs not in the training sample — use the last parquet files / FineWeb tail): whitespace-only token share of code tokens, chars/token code & text, and exact round trip on every doc; compares with GPT-2; writes `results/tokenizer_gate.md`; exit 0 only if all four §4.3 criteria pass.

- [ ] Tests (no network): train a tiny tokenizer (vocab 512) on an in-memory corpus in tmp_path; round trip exact on unicode, CRLF, tabs, 40-space indents, emoji; `encode` does not produce special ids for the literal string "<|user|>" but `encode_with_special` does; special ids are stable (fixed ids) across two trainings; a run of 8 spaces is one token after training on indented code; digits split; gate metric functions on fixtures (whitespace share computed by decoding each token); `make_tokenizer("gpt2")` still returns the old tokenizer.

- [ ] Commit: "Add a code-aware BPE tokenizer, its trainer and the tokenizer gate".

### Task M3: SiTU-GLU, experts, router and Quantile Balancing

**Files:** Create `quipu/moe.py`, `tests/test_moe.py`.
```python
class SiTUGLU(nn.Module):      # (β1·tanh(Wg x/β1) ⊙ sigmoid(Wg x)) ⊙ (β2·tanh(Wu x/β2)) → Wd ; spec eq. (12) with a down projection
class SwiGLU(nn.Module)        # existing formulation, same interface
class ExpertBank(nn.Module):   # n experts as stacked weights [n, d, h] for gate/up and [n, h, d] for down; forward(x_sorted, counts) runs each expert on its slice
class Router(nn.Module):       # linear d→n, fp32 scores = softmax(logits); select Top-k on (scores + bias); weights = scores[selected] renormalised to sum 1
class QuantileBalancer:        # holds bias b (buffer, fp32, shape [n]); update(scores) implements spec §3 Quantile Balancing:
                               #  target load q = k·T/n per expert; for each expert j the new bias is set so exactly q tokens' margins s_ij + b_j − α_i exceed it,
                               #  where α_i is token i's (k+1)-th largest biased score; moved by balance_update_rate toward that value (EMA); no gradients
class MoELayer(nn.Module):     # shared experts (full width, always on) + routed ExpertBank; forward returns y and stats (per-expert token counts)
```
Dispatch: flatten tokens, gather Top-k (token, expert, weight) triples, sort by expert, run ExpertBank on contiguous slices, scatter-add weighted outputs back. Router and balancing math in fp32 under autocast.
- [ ] Tests: SiTU-GLU ≈ SwiGLU for small inputs (|x|<0.5, rtol 1e-2) and bounded by β1·β2 for large inputs; routing weights sum to 1 per token; selected experts differ per token; MoELayer output equals a naive per-token loop over experts on random inputs (atol 1e-5, fp32); counts sum to T·k; a router biased so expert 0 wins everything → after 200 balancer updates on the same scores every expert's load is within 25% of target; balancer never gets gradients; bf16 autocast forward is finite; empty-expert (zero tokens) path works.
- [ ] Mutation: skip the renormalisation → the weights-sum test fails; skip the bias in selection → the balancing test fails.
- [ ] Commit: "Add SiTU-GLU experts, a routed MoE layer and Quantile Balancing".

### Task M8: A/B orchestration

**Files:** Create `scripts/ab_runs.py`, `tests/test_ab_runs.py`.
`ab_runs.py --config configs/quipu-moe-ab.toml --out results/ab [--dry-run]`:
1. LR sweeps at 100M tokens: AdamW lr ∈ {3e-4, 6e-4, 1.2e-3}; Muon muon_lr ∈ {0.01, 0.02, 0.04} (AdamW part at its best lr); pick lowest final val loss.
2. Arms at 200M tokens, one setting changed per pair: optimizer (AdamW best vs Muon best); attnres_blocks (0 vs 4); activation (swiglu vs situ_glu). Baseline for pairs 2–3 = winner of pair 1.
3. Seed re-run of each pair's winner (seed+1) → noise estimate = |Δ| between seeds; a pair's difference below noise keeps the simpler option (AdamW, no AttnRes, SwiGLU).

5. Writes `results/ab/summary.md` (table of every run: config diff, final val loss, bpb, tokens/s, spikes, decision) and `results/ab/winners.toml` (overrides for the full run).
Each run is a subprocess of `python -m quipu.train` with `--override` flags (add a generic `--override key=value` to train.py's CLI if missing, typed by the dataclass field).

### Task M9: Box launcher, spend guard, sync

**Files:** Create `scripts/remote/run_moe.py`, `scripts/remote/sync.sh`, `tests/test_run_moe.py`; update `scripts/remote/README.md`.

budget_usd passed to each process is the REMAINING session budget from the launcher's ledger (prior spend subtracted); the $20 cap is per session. When the throughput gate trims total_tokens, milestones are rescaled by their fractions of the run (and deduplicated), so they never fall past the end.
