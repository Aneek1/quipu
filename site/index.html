Quipu

A small language model trained from scratch on a single 8 GB laptop GPU.

A quipu is the Incan recording device: knotted cords that stored records, read by running them through the hands. Information mapped onto positions, retrieved by traversing them — which is the idea behind where this project is going.

Architecture

Decoder-only transformer: RMSNorm, rotary position embeddings, SwiGLU feed-forward, grouped-query attention (12 query heads over 4 key/value heads), tied input and output embeddings, 1,024-token context. Trained in bf16 at ~16,500 tokens per second.

Data

80% FineWeb-Edu and 20% permissively licensed code from github-code-clean (MIT, Apache-2.0, BSD, ISC, CC0, Unlicense only). Minified files, vendored directories and files over 16k tokens are filtered out — which removed as many tokens as the entire code budget.

Results

Training is running now. Loss curves, what the model can do at each training milestone, and a retrieval test over 1M tokens will be published here when it finishes.

The failures that don't announce themselves

Most of the work in a long unattended run is catching things that fail silently. Each of these was found in review, before the run:

  • Attention was silently falling back to a slow kernel. Fixing it took the projected run for the original budget from ~65 hours to ~39.
  • On this machine, about 1 in 130 file renames fails transiently — enough to kill a 50-hour run over a log write. Every atomic write now retries.
  • A resume path could restart from zero after days of training without an error. It now refuses unless nothing could have been saved.
  • One non-finite batch would have poisoned the weights and, through checkpoint retention, deleted every clean checkpoint. Non-finite steps are now skipped, and three in a row stop the run.

What it will and won't do

quipu-114m is a base model: fluent text and code-shaped output, frequently wrong, no instruction-following. That is the expected result at this scale, and the starting point.

Next

  • Instruction tuning, so it answers rather than continues.
  • A memory architecture aimed at an effective 1M-token context on the same 8 GB card: a short attention window plus a retrievable map of everything before it.
  • 350M parameters with a code tokenizer; tool calling for coding agents.
